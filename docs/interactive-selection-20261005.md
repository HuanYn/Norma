# 非实时探索 → 美学与偏好闭环 → 独立评测

## 使用

主应用 `http://127.0.0.1:8767/`；交互探索 `http://127.0.0.1:8768/`；原来的离线双图页仍在 `/world-demo/`。这些是本机地址，不是公网部署。

探索：选照片 → 勾选发送到自有服务器 → 进入场景 → 等待初始化 → 点击前进/转向 → 观看 → 再选动作。首版限制每会话7次操作，165帧、16fps、10.3125秒；不是无限探索。刷新页面保留同一浏览器会话，服务重启不恢复GPU状态；10分钟闲置释放。失败/取消后重新开始，完成片段仍可下载。模型可能虚构原图之外的几何，不是三维重建。

重启本地入口：保持专用8769 SSH隧道与远端worker运行，然后 `python scripts/start_world.py`。完整worker参数见 `scripts/world_worker.py --help`。令牌来自本地私有文件，绝不放进前端；远端只绑定loopback，不暴露公网。

选片：先在相册完成基础质量、语义索引，再在选片页按需运行模型质量评估；勾选“使用模型美学与质量排序”。生成一组照片后可两两比较，再点击“按刚才的偏好重新选片”。取消偏好开关可回到不参考记忆的排序；新反馈不会自动训练模型。

## 算法实际做了什么

- 探索：固定版本LingBot v2 1.3B。文本/首图只编码一次，DiT自注意力KV、跨注意力KV、随机数状态、相机位姿、已生成latent跨动作保留。每次6个latent（两个3-latent块）。相机动作转换为相对位姿与Plücker射线条件；不是用上一段末帧重新跑一次I2V。
- 连续解码：当前重新解码全部latent前缀，检查之前显示的像素是否改变（归一化误差≤2/255）。这是正确性优先的实现，**不是增量VAE解码优化**，累计越长耗时越高。
- 美学：冻结MUSIQ-KonIQ技术质量与MUSIQ-AVA美学模型。选片用当前原图SHA绑定的评分缓存，缺失/过期停止，不悄悄用规则分代替。
- 融合：语义任务分数为 `0.72*cosine + 0.18*(AVA-1)/9 + 0.10*KonIQ/100`；无语义时 `0.65*(AVA-1)/9 + 0.35*KonIQ/100`。归一化输入截断到[0,1]，原始分数保留。这些权重是固定Demo策略，未训练、未用留出集调参。原有拒片、最低规则质量、相似组、人数等硬约束不变，由约束优化器处理。
- 个性化：已有冻结OpenCLIP案例记忆，在相近任务检索历史胜负对，给候选软分数加减最多0.15。结果列出事件ID与贡献。不是DPO、SFT或新训练奖励模型。代理标注默认排除；API双重显式 `use_preference_memory=true, allow_proxy_memory=true` 才能参与，来源仍标为assistant_proxy。
- 替换：沿用相同美学快照，重算锁定照片与候选的融合/偏好分；证据改变要求重新选片，不能混合新旧分数。

## 独立评测协议

冻结方法版本、权重和模型哈希后，按拍摄来源/场景划分开发记忆与留出集，不能只随机拆照片。至少30个独立来源组作为初始目标（不是统计充分性的保证），每组多种查询、重复/困难负例。盲化方法身份，人工两两选择left/right/tie；记录标注来源与一致性。代理标签单独报告。

比较 baseline、learned quality、learned quality + relevant memory、random memory；候选、查询、硬约束固定。主要指标为独立三类偏好一致率；辅以硬约束满足率、选片替换次数、端到端冷/热耗时。按来源组进行配对bootstrap，报告95%区间；不能把同一场景多个pair当独立样本。

`scripts/evaluate_selection_holdout.py --labels ... --predictions ... --output ...` 是独立于推理代码的评分入口。标签清单与预测必须匹配SHA和方法版本；拒绝开发/记忆与测试的原图SHA重叠、来源组重叠、缺样本或非有限值。此接口核对声明与文件一致性，不能凭一个布尔值证明标注真的盲化，仍需保留冻结时间、标注过程和独立复核记录。

标签格式：`schema=norma-independent-pairs-v1`、`labels_frozen_before_predictions=true`、`method_revision`、`label_provenance`、`human_observed`、`development_and_memory_sha256`、`development_and_memory_groups`、`cases`。每个case含 `id/group/left_sha256/right_sha256/winner`。预测含 `label_manifest_sha256/method_revision/scores`；scores按方法名（必须含baseline）和case ID映射到 `[left_score,right_score]`。

## 面试重点

- 为什么不是普通图生视频？动作在看到上一段结果之后才提交，同一KV/相机/RNG状态继续生成；接口顺序与真实运行记录可追溯。
- 为什么不是无限世界或3D重建？首版有7步上限，模型只生成合理的外观，不保证不可见几何真实或回环一致。
- 美学模型是不是你训练的？没有，使用预训练模型；工程贡献在来源校验、按需评估、选片融合、反馈闭环和评测设计。
- 个性化是不是DPO？不是。它是冻结表征上的案例记忆。只有真正训练策略/偏好目标并验证时才可称后训练。
- 为什么不能用MUSIQ分数增加证明审美进步？排序已直接优化该分数，再用它作唯一评测会循环论证，必须使用独立标签/指标。
- 主要优化空间？增量VAE、延长状态窗口与回环约束、冻结测试集后的融合校准、减少内容/风格混淆；不能把这些计划写成已完成。
