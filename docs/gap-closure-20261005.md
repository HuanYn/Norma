# Norma Demo 补齐记录 · 2026-10-05

当前定位：预训练多模态模型的端到端应用与推理工程 Demo，不是自研基础模型，不是已证明偏好提升的论文结果。本轮不训练模型，不提交或推送代码。

最新优先级：用户要求先完成Demo，停止新增评分模型和研究型评测。默认路径是OpenCLIP检索、已有双MUSIQ和可选案例记忆，复杂Qwen解析默认关闭；操作见[Demo使用说明](demo-quickstart.md)。下文保留开发过程，不应把实验性解析理解为主流程已验收。

## 解析算法：不是把学习算法换成规则

输入文字先拆成两类。可严格核验的字面硬约束，例如“选3张”，后端保存原文子串与值；内容和软风格，例如“建筑、暖色、电影感”，交给冻结的 Qwen3-VL 2B。输出仍必须通过有限字段JSON验证和原文覆盖检查。不支持的排除/分类配额会停下来要求澄清，不偷偷放宽条件，也不自动转云端。

随后仍使用 OpenCLIP 图文向量召回、MUSIQ 美学/技术质量、多样性约束与可选偏好记忆重排。这里没有 SFT 或 DPO。混合设计的价值是把机器能精确验证的条件从语言模型的自由输出中拿出来，而不是假称语言模型能可靠执行任意要求。

同一个已经加载的模型、同一旧失败请求“选3张建筑，偏暖色电影感”：旧JSON契约62.156秒且验证失败，新契约8.907秒且通过。新输出预算384 token，旧契约更长；这是一例工程消融，不是普遍7倍模型加速。旧v1的9例统计只检查数量/状态，不能证明语义正确；复核发现未经要求的风格与模板残留。更严格v2的前2例仍失败，未完成全套，因此暂不纳入Demo默认路径。失败记录保留，首次加载与热请求分开报告。

证据：`.norma/gap-intent-20261005-v1/result.json`、`.norma/gap-intent-ablation-20261005-v1/result.json`。这些是私有本地运行文件，不随Git分发。

## 视频优化：什么加速了，什么没有

DiT 的 KV、自注意力/交叉注意力状态、相机姿态、随机数生成器和 latent 原本已跨步骤保存；本轮补的是 VAE 特征缓存。旧版第n步把此前所有 latent 再解码；新版只解码新增6个 latent，保留因果卷积缓存。输出会累计已有CPU帧，仍需重新编码预览MP4，因此并非无限长或恒定总开销。

| 固定同latent，384×640，seed42 | 全前缀解码 | 增量解码 | 最大像素差 |
| --- | ---: | ---: | ---: |
| 第7步，165帧 | 18.793秒 | 2.685秒 | 0 |
| 第14步，333帧 | 37.887秒 | 2.682秒 | 0 |

这些只包含解码，不包含模型加载、去噪、保存、下载。输入是随机latent，因此只能证明该测试下实现等价和时延变化，不能证明视频更好看。第一轮误用了 BF16 而非生产默认 FP32，在第3步测到0.03125偏差，未通过2/255阈值；失败报告保留，没有放宽阈值，改用与生产一致的FP32重新测。精度不一致与偏差相关，尚未单独定位到底是哪一个算子产生差异。

真实雪山14步每步总生成6.823–11.060秒（不含初始化），20.8125秒成片，下载SHA匹配。直播会话中的前缀误差0在增量模式下表示旧帧原样保留，**不能替代上面的同latent解码等价试验**。帧外内容由模型补全，不能声称真实三维重建。空间一致性、回头能否看到同一物体仍需定量和人工检验。

当前渐进部署：worker1保留7步参考实现；worker2为14步增量实现。页面按各会话返回的能力显示，不能说两张均默认14步。GPU0上存在其他任务，不为升级强制终止。代码默认仍为保守的7步/prefix，远端以显式参数开启优化。

证据：`.norma/gap-vae-evidence-20261005/{bf16-result,fp32-result}.json`、`.norma/gap-world14-20261005-v1/result.json` 和相邻MP4。

## 独立评测工具怎么用

```powershell
python scripts/prepare_review_pilot.py --source D:\新的测试照片 --development-db .norma/data/norma.db --development-db .norma/demo-data/norma.db --output .norma/my-review --pairs 12
python scripts/start_pair_review.py --bundle .norma/my-review/bundle --port 8772
```

打开 `http://127.0.0.1:8772/`。界面不显示模型分数，随机排列照片对和A/B左右；可选A、B、平局，跳过不算平局；保存有版本检查；完成后由本人确认并冻结，再下载标签。不要由助手替用户勾选“本人判断”。个人照片、标签库与图片衍生文件都放`.norma`，不推送。

采样工具检查指定开发库中的路径、原图SHA以及保守pHash/dHash；每个候选集合只计一个来源组，不靠文件名虚构独立样本。旧数据库没有SHA列时仍保留路径与可用字段检查。此检查不是完整语义泄漏审计，也不证明所有相册都在已声明清单里。

本轮尝试新公开数据下载，两次连接重置；本地精修候选经开发库排除后为0。因而**尚无合格新盲评包，也没有真实人工偏好结果**。不要把工具的受控测试或已用开发照片包装成独立留出评测。标签冻结后，仍需对同一集合运行预先固定的基线/融合/偏好方法、导出预测并用`evaluate_selection_holdout.py`评测；预测文件必须绑定标签SHA与方法版本，不能临时调参再声称留出提升。

```powershell
python scripts/demo_doctor.py
python scripts/start_demo.py
```

主页面`http://127.0.0.1:8767/`。生成式解析需在“文字大模型解析（可选）”中勾选；默认选择仍可走本地图文检索。`--vlm-provider local`或`--vlm-provider openai-compatible`显式覆盖，省略则保留环境设置。云端配置需私有环境变量，不把密钥写笔记、前端或Git；云端调用仍需要页面确认，仅发送该次文字。doctor不会调用云端、加载模型、重启服务、启动生成或泄露token。

远端优化启动参数是在原worker命令后加`--decode-mode stream --max-steps 14`；只允许空闲GPU启动。模型代码和权重遵循现有固定版本与上游非商用许可，不能把求职展示理解为可商用授权。

## 面试追问

- 为什么使用规则编译还叫多模态项目？模型负责图文语义、美学评分与视频生成；确定性约束用于可执行性校验。说明各部分边界，而不是给规则贴大模型标签。
- 为什么不能把8/9叫“偏好准确率”？它测的是文字意图契约是否符合预期，不涉及本人看图偏好标签。
- 解码加速有没有损失？在固定FP32随机latent测试中逐像素一致；不外推到所有精度、分辨率或模型版本。
- 为什么视频仍会变形？推理缓存优化不改变基础生成模型的空间建模能力；还缺回环、漂移、动作遵循度评测。
- 个人偏好是否有效？机制可用，但目前助手代理记录不代表本人喜好；收益需本人盲评、无偏好对照、冻结数据和来源分组验证。
- 能写“独立评测完成”吗？不能。评测工程已实现，数据和真实标签仍缺。

一句话总结：本轮把生成式选片的可执行条件与模型语义解耦，补上因果VAE缓存并实测更长非实时探索，同时把盲评冻结、来源检查与环境诊断做成可复用工具；工程功能与时延有证据，独立审美和个性化收益尚未得到证明。
