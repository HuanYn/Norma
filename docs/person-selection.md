# 人物命名与人物数量选片：M2/M3 第一批

更新：2026-10-05。这是人物基础闭环，不是完整 M3/M4，也没有改变人脸模型或证明识别准确率提升。

## 怎么用

停止旧 Python 服务，重新启动后打开网页。需要云端功能时使用 `python scripts/start_deepseek.py`，在本机隐藏提示输入 Key；仅使用本地人物功能可用 `python -m ai web`。不要把 Key 放到命令行、笔记或 Git。

1. 导入 JPG/JPEG 相册，点击“人脸分组”。已有旧版分析也需要重新运行一次，以生成新的身份证据。
2. 展开人物卡片核对组内照片。给自己的分组点“是我”（Me），其他人可以输入自定义名字，点击保存；误标可重置为 Unknown。系统不会猜测谁是用户本人。
3. 点击质量分析，然后在选片框输入 `选9张，至少2张有我`。自定义名字支持 `选9张，至少2张有“Alex”`，也支持英文 `select 9 photos, at least 2 photos with "Alex"`。
4. 若所有条件都是数量/人物/质量，无需图文模型；增加建筑等语义时需先完成向量索引。
5. 返回结果和替换操作均检查人物配额；候选不足返回不可满足，不偷换成普通 Top-K。名字待复核、人物分析不完整、原图已变化会明确拒绝，而不是当作人物不存在。

当前解析器是有边界的本地基线，不是通用自然语言理解。数字请用阿拉伯数字；自定义人物名在自然语言里需加引号。`不要自拍`、`至少2张夜景` 等尚无可验证内容标签，会明确报未支持；不要把普通 CLIP 相似度称作这些硬条件已满足。后续由 DeepSeek 输出 hard/soft schema，本地继续独立验证。

## 后端原理

- 人脸检测和向量仍为原有 YuNet/SFace；本次新增身份命名生命周期，不训练新的识别模型。
- 名字附着在精确的人脸成员、原图哈希、描述子哈希、provider/聚类策略指纹上，状态为 `unlabeled`、`confirmed` 或 `needs_review`。
- 无变化重建保留确认过的名字；增删照片只失效相关缓存。人物成员增长、分裂、合并、源内容或模型变化不自动传递名字，而是要求重新确认；旧事件留在不可修改的审计表中。
- `label_revision` 拒绝旧页面覆盖新分组，即使旧组和新组恰巧产生相同 cluster ID。未命名组的变化也推进版本，避免删除后重现的 ABA 问题。
- 每个候选照片只有一个布尔选择变量。CP-SAT 同时限制总数、相似组上限和每个人的照片数量下限；一张合影可同时计入两个不同人的下限，但同人在同张图的多个脸框只计一张。
- 人物配额需要 OR-Tools；未安装时明确不可执行，不能回退成会忽略配额的普通贪心。
- 保存选片绑定人物快照；替换时重新验证人物、质量、相似组和原子集范围。名字/证据变化后要求重新选片。最终身份快照校验与结果写入处于写事务保护内。

接口示例：

```http
PATCH /albums/{album_id}/people/{cluster_id}
{"label":"Me","expected_revision":0}
```

返回更新后的 label/status/revision 与人脸列表。并发版本变化时刷新人物列表后复核，不盲目重试保存。也可在 `POST /selections` 中传 `person_minimums: {"Me":2}`；该字段与 prompt 的已识别人物下限取较严格值。

## 面试可能问到

- **这是新的人脸算法吗？** 不是。预训练模型负责检测与表征，本次核心是命名证据、缓存一致性与约束执行；不能把工程回归算作识别准确率提升。
- **为什么不用大模型判断是不是我？** 用户身份需要明确命名；大模型可以帮助理解任务，不能凭照片猜真实身份。
- **为什么不按簇相似度继承名字？** 自动继承会将聚类误合并转成身份误标。当前保守地保留精确未变证据，其余要求复核；代价是成员增加时也可能多一次人工确认。
- **为什么既有模型又有规则/优化器？** 模型产生视觉或语义证据，优化器负责可验证的集合约束，版本和状态规则保证数据可靠；并不是要求所有后端代码都成为学习算法。
- **哪里使用了个性化？** 这批人物条件是用户显式约束，不是审美偏好学习。授权代理标注见 [初始偏好](proxy-preferences.md)，其记忆检索与冻结模型重排尚未接入。

## 验证边界

回归包含命名刷新、源/模型漂移、分组增删合并拆分、跨相册、旧版本保存、审计不可变、人物配额/去重/质量/子集冲突、替换及无求解器拒绝。对照报告使用独立临时数据库和合成图，UI 前后图使用同一模拟数据，均不是私人相册的人脸识别评测。
