# 旅游选片请求被虚构条件拦截

用户原话：`挑出最适合这趟旅游展示的9张照片`。trip相册158张，美学门槛5、技术质量40后102张候选。

## 根因与修复

旧本地解析提示中列举“不要自拍、必须某类”等不支持条件。固定模型的原始输出把“自拍”和“必须某类”写入用户条件，尽管请求里没有这些词；`_validate_source_coverage`正确拒绝，网页却直接显示英文异常且状态仍为“模型正在理解”。不是照片路径失效，也不是应该关闭安全校验。

v3提示移除具体负例，强调request是唯一事实来源、展示用途是软偏好、没有问题应返回空数组。保留所有原文证据检查、schema约束和硬条件覆盖校验，没有删掉模型输出中的错误再冒充成功，没有自动降级或切换云端。

另外补上狭义的“挑出…的N张照片”数量表达，编译为可验证的“选N张”并保留原文。之前该句的9与默认9碰巧相同；现在记录为显式数量，4/9/12都有回归测试。不扩展任意复杂数量语法。

前端将两类模型校验失败转换为中文提示；失败时明确停止，保留候选相册、恢复按钮，不再声称正在理解。

## 验证与边界

- `.norma/trip-intent-fix-20261006-v2/result.json`保存旧提示、新提示、每次原始输出。旧请求失败，新提示返回ready/9张/无虚构问题。新提示热解析8.51秒；旧88.55秒含冷加载，不能据此宣称10倍加速。
- “选4张，不要自拍”的模型仍没有正确提取排除条件，但后端检测到未覆盖的硬要求并返回needs_clarification，不生成误导结果；不以此声称复杂意图全部可靠。
- 流程、compact解析、structured解析84项测试通过，包含虚构条件拒绝、4/9/12显式数量和未知硬要求保护。
- 完整浏览器验收`.norma/trip-selection-ui-20261006-v1/result.json`为passed：开启文字模型，用原句从trip的102张候选中选出9张，HTTP200、text_interpretation=language-model、contract=v3、default_count_applied=false。重启后的整次请求112.02秒，模型段72.507秒含加载，不应与8.51秒热解析混为同一指标。之后明确mock一次英文异常，验证中文提示、停止状态和按钮恢复，不冒充真实失败推理。

本轮只使用本地CPU模型，未上传相册、未启动视频GPU工作进程、未提交代码。新提示只在报告的请求和保护案例上验收，不代表任意复杂要求均正确。
