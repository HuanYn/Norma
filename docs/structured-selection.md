# 结构化自然语言选片：第一版 Demo

当前为实验入口，默认关闭。2026-10-05本地Qwen3-VL-2B真实两次尝试均未通过契约校验；原始响应见 [实测JSON](benchmarks/local-intent-smoke-20261005.json)，不能称本地模型解析已可用。没有自动付费云端回退。

这层解决的是“用户提出了哪些要求”，不是“照片是否满足要求”。解析模型不读取图片，也不判断照片中是谁；人物证据仍由现有命名与分组系统提供，最终集合由现有选片服务和约束求解器选择。

## 执行顺序

1. 用户输入自然语言。
2. 配置好的文本模型把要求分成硬约束、语义内容、风格、未支持要求和不确定要求。
3. 服务端严格检查 JSON 类型、取值范围、未知字段、重复 JSON 键、原文证据和已知强制词覆盖。
4. 只有 `status=ready` 的结果可转换为现有 `SelectionIntent`；任何未支持或不确定要求都阻止执行，不静默删除要求，也不自动退回规则选片。
5. 语义内容与风格文本交给检索；人物下限等硬条件交给约束求解。结构化结果和原始问题一起保留审计。

例如“选9张，至少2张有我，暖色建筑”：总数为9，`me` 的下限为2，建筑是检索内容，暖色是软风格。模型只能提取用户说的标签 `me`，不能凭这段文字把某个人脸认定为用户。

## 第一版支持边界

支持的硬条件只有：选片总数1–50、现有质量分下限0–100、是否排除自动废片、相似组上限1–10、最多10个人物标签的各自下限1–50。

每个显式硬条件必须引用原文中的独立短句；第一版通过有界语法再次核对数值。支持“选9张”“至少2张有我”“至少2张有‘Alex’”（实际输入使用中文双引号或英文双引号）、`select 9 photos`、`at least 2 photos with "Alex"`，以及部分中文数字和“挑选/最少”等同义形式。

类别配额、必须无自拍、排除某人、某人恰好或最多若干张、时间/GPS/画幅条件尚未验证，必须返回未支持要求。“每张都有人”“绝不能有自拍”不能悄悄降为相似度分数。无法通过独立语法验证的新说法也要求澄清，而不是把模型 JSON 当成证明。

这个防护只能检查已覆盖语法与强制词，不保证发现任意自然语言中的全部隐含约束；在没有独立测试集前不能宣称“自然语言硬条件零漏识别”。前端应展示解析结果供用户复核。风格属性仍是软要求，不是照片事实。

## 模型与安全

- `create_structured_parser(settings)` 复用当前 `NORMA_VLM_*` 配置，不新增凭据。
- 云端使用专用文本适配器，复用现有 HTTPS 地址校验、禁用重定向、超时、响应字节限制、密钥脱敏与完成状态检查；不上传图片。构造对象不会联网，`parse` 才发起一次请求，不自动重试。
- 本地调用已固定权重的 Qwen3-VL 运行时新增的 `generate_text_json`，不伪造空白证据图；与多模态调用共享模型及锁，维持前后模型完整性检查。旧视觉方法仍要求真实证据图片。
- 本地方法仍是现有 **CPU-only** 行为，不代表已支持3090或8GB笔记本GPU。输出最多1024 token，输入最多4096 token；前置文本字节预算和后置输出字节预算独立检查。令牌预算不是严格的墙钟超时。
- 所有模型输出在边界重新校验，不接受模型生成的服务端来源信息。记录请求、输出、协议哈希和提供方指纹。云端指纹不代表固定远端权重版本。
- 用户输入含本地路径时拒绝解析，避免脱敏后改变条件含义；不把供应商原始错误、响应正文或凭据放进公开异常。

## 接入方式

```python
parser = create_structured_parser(settings)
result = parser.parse(request.prompt)
# 解析接口可先返回 document/status/provenance，供网页展示。
intent = result.to_selection_intent()  # 有未决要求时抛异常，禁止继续选片
# SelectionService 接受服务端传入的 intent，查询使用 result.semantic_query。
# 原始 request.prompt 仍用于审计，不把模型返回的 JSON 直接作为客户端可信输入。
```

`StructuredSelectionResult` 是内部结果，不直接接收客户端反序列化提交。服务端应重新解析或使用自己保留的已验证快照；不要把客户端自报的 `ready` 当成安全条件。原来的规则解析流程应作为显式 baseline 保留，不能在模型失败时偷偷切换。

## 验证与求职表述

新增离线测试覆盖严格类型、未支持条件、遗漏/伪造证据、错误 JSON、请求预算、云端文本协议、截断拒绝以及本地 token 预算；所有提供方均注入测试替身，没有付费请求、模型下载或训练。

可以表述为“预训练语言模型结构化理解＋证据约束校验＋检索和离散优化”，不能表述为“训练了新的意图模型”或“用DPO完成了选片”。应进一步用独立中文请求集测槽位准确率、硬约束漏识别率、澄清率和延迟；通过单元测试不等于真实模型表现达标。
