# Norma：本地检索、云端分析，后训练按需

更新日期：2026-10-05。

本轮工程验证：421 项后端测试通过，网页类型检查与构建通过；没有真实云端调用或新的模型效果指标。详见 [验证记录](benchmarks/model-first-integration-20261005.md)。

## 这次方向调整

Norma 的主要任务是理解、搜索和挑选照片。默认路线改为直接运行现成预训练模型，保留可解释的业务约束；收集反馈与训练参数分开。无需先训练自己的模型，才能使用网站。

用户确认的部署路线是“本地检索＋云端大模型分析”。目录、向量、人脸缓存与初步搜索留在本机；需要语义分析时，把 Top-K 候选的压缩副本与问题发给配置的云端视觉模型。原本的本地 Qwen 推理保留为 `local` 选项。

## 模块怎么安排

| 模块 | 当前实现 | 默认是否更新模型参数 | 后续可选改进 |
| --- | --- | --- | --- |
| 图文召回 | 固定版本 multilingual OpenCLIP，归一化后 cosine 排序 | 否 | 对照评测现成 embedding / reranker |
| 人脸 | YuNet 检测、SFace 表征、同图互斥等聚类约束 | 否 | 阈值校准和失败样本分析 |
| 看图回答 | 检索 Top-K 后通过兼容接口调用云端 VLM，验证引用 | 否 | 对照不同现成 VLM；本地 Qwen 可选 |
| 质量与去重 | 清晰度/曝光等特征、pHash/dHash | 否 | 现成 IQA/美学模型做对照，尚未接入 |
| 偏好反馈 | 记录 A/B、平局、跳过、都不好 | 否 | 后续将已确认偏好作为 prompt 示例/记忆，尚未接入 |
| 选片约束 | 张数、质量门槛、相似组容量和锁定项 | 否 | 保持可校验的硬约束 |
| 旧偏好实验 | 67D Bayesian residual、7D legacy logistic、PDRR | 仅显式 `adaptive` | 保留为历史基线，不是默认依赖 |

预训练模型的特征是通过学习获得的。使用冻结模型仍属于模型驱动的多模态系统；推理阶段不更新权重，不等于系统只使用规则。

## 默认模式与兼容模式

```powershell
$env:NORMA_PREFERENCE_MODE = "record-only"
python -m ai web
```

未设置该变量时也默认 `record-only`。网站仍需要先安装已固定版本的模型，并对相册运行语义索引；建立 embedding 是模型前向推理和缓存，不是训练。

云端配置与请求示例见 [cloud-analysis.md](cloud-analysis.md)。Key 只从服务端环境变量读取，不写入浏览器或笔记。`openai-compatible` 表示请求协议，不限定一定要用 OpenAI。尚未配置时仍可使用本地搜索，但云端分析会显示未配置。

默认模式下：

- 普通 A/B 反馈继续留档，`preferred` 不触发 Bayesian 拟合或 legacy SGD。
- 搜索、选片、替换和 RAG 不使用历史学习权重调整排序。
- 原有反馈和模型记录保留，便于复盘；记录反馈不意味着结果已经个性化。
- PDRR 主动问题接口明确不可用，因为它服务于旧的 Bayesian 学习流程。
- 模型推理、引用校验、质量门槛与集合约束继续工作。

复现以前的偏好实验时可显式开启：

```powershell
$env:NORMA_PREFERENCE_MODE = "adaptive"
python -m ai web
```

`adaptive` 允许后续有效 `preferred` 反馈触发原小模型拟合，并使用兼容的已训练偏好模型。它是旧实验的开关，不是 LoRA 或大模型后训练。切换模式需要重启服务；历史事件多于旧模型所覆盖的事件时，应遵守已有的模型一致性检查，不能把旧模型当作最新模型。

## 标注由助手负责，先固定任务和口径

标注工作可以交给助手执行，但不同数据有不同用途：

1. **可见内容**：主体、场景、动作、可辨文字；只写图中能观察到的内容。遮挡、模糊或证据不足时允许 `uncertain`。
2. **查询相关性**：以“query + image”为单位，使用 0=不相关、1=部分相关、2=直接满足；必须附可见证据和简短理由。
3. **选片比较**：以“query + 两张照片 + 明确标准”为单位记录 A/B/tie/uncertain。构图或偏好判断是按 rubric 的模型标注，不代表用户真实审美。
4. **有据回答**：保存 claim 与 photo ID 的对应关系，分别检查格式正确、引用有效、内容是否真被图片支持。

每条标签至少保存：样本 ID、原图内容 SHA、query、rubric 版本、label、理由、标注者类型/模型版本、审阅状态、数据 split。模型生成的标签使用 `model` 或 `assistant` 来源，不标成人工真值。模型的自报 confidence 也不当作校准后的概率。

样例字段如下，只是格式示意，不是一条已完成的标注：

```json
{
  "sample_id": "example-only",
  "source_sha256": "REPLACE_WITH_ACTUAL_HASH",
  "query": "夜晚有灯光的建筑",
  "task": "query_relevance",
  "rubric_version": "relevance-0-1-2-v1",
  "label": null,
  "evidence": [],
  "annotator_kind": "assistant",
  "review_status": "pending",
  "split": "unassigned"
}
```

先按相册、近重复组等单位划分开发集/测试集，再标注；同一场景的近重复图片不跨 split。测试标签冻结后再比较方案，不用待评模型自己的回答同时充当评分标准。独立复核可以降低标注错误，但如果复核也完全由模型完成，报告仍要说明这是模型审阅数据。

已有 70 图偏好实验是受控半合成实验，分类来自下载词代理，不能直接改名为新路线的真实人工标注结果。历史原始 JSON、图表和指标保持原实验身份。本轮没有生成新的标注数据或新的模型质量指标。

## 少量后训练的触发条件

先建立现成模型的基线，分析错误是否能通过输入、prompt、检索范围或模型选择修复。只有反复出现的任务性错误才值得尝试少量后训练。

第一候选是小规模 LoRA/SFT：针对结构化选片解释、领域词汇或输出格式，使用经过复核的示例；冻结主干，只训练 adapter。若问题明确是“同一输入下多个回答的偏好”，且已有可信 chosen/rejected 对，再考虑 DPO。二者都属于可选后续实验，当前未实现或运行。

评测至少比较“原模型”“原模型 + 改进 prompt/检索”“可选 adapter”，同时报告效果与推理成本。adapter 不能只在训练集上表现好；没有稳定收益就继续使用原模型。

## 求职项目怎么讲

可以这样介绍：

> 我做了一个本地检索与云端分析结合的照片多模态系统，复用 OpenCLIP、人脸模型和云端视觉语言模型，完成检索、选片与带图片引用的回答。我主要负责数据与标注流程、检索和模型调用编排、输出校验、缓存一致性以及可复现实验。默认无需自训练，后训练只作为有失败证据支撑的可选优化。

面试常见追问：

- **不训练，算法工作体现在哪？** 检索策略、数据质量、证据选择、约束决策、消融设计和错误分析都有可比较结果；需要展示真实评测，而不仅是调用接口。
- **为什么保留规则？** 张数、去重容量和引用 ID 等要求可以被确定性检查；模型负责表征和语义判断。
- **助手标注可靠吗？** 保存来源和 rubric，允许不确定，检查样本并复核分歧；模型标签不是天然真值。
- **为什么没有立刻做 DPO？** 先证明现成模型的瓶颈，建立可信偏好对与独立评测，再决定是否值得后训练。
- **旧 Bayesian 模块怎么办？** 保留可复现实验和显式 `adaptive` 开关；当前默认产品不依赖它训练。
