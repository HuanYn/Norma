# Norma：美学驱动的个性化选片与图生视频开发计划

日期：2026-10-05。状态：**方案草案，仅规划，尚未执行新模型接入、下载、租卡或训练**。这是根据本轮新需求重排的路线；不覆盖历史实现记录或将计划功能算作完成。

## 1. 定位与成功演示

产品定位：**本地理解相册、按自然语言与个人审美选片，再由远端开源模型制作短视频的多模态智能体**。

完整演示：

导入相册 → 点击质量/美学分析 → 输入选片要求 → 查看满足约束且符合风格的集合 → 接受/替换/锁定 → 生成分镜 → 确认待上传图片 → 图生视频 → 逐镜头时序/美学评测 → 导出约15秒成片。

示例：“选9张做旅行短片，至少2张有我，多一些建筑，偏暖色电影感，不要太重复；视频缓慢推进，转场自然。”

这句话必须拆为可验证硬条件、软风格与视频指令。未知条件需要询问或标记不能验证，不能只搜索整句后直接返回Top-K。

岗位对应重点：
- 数据体系：图片/序列帧/镜头/偏好/可选alpha标签可追溯，含来源、授权、哈希、模型与标注版本。
- 审美建模：预训练技术质量模型、通用美学模型、个人偏好三层分开。
- 视频优化：先做条件构造、输入选择、预算一致的候选筛选与时序评测。
- 训练：不是首版前置；有失败证据后再选一项小规模后训练。
- 落地：Python后端＋网页＋远端GPU工作进程，可取消、可恢复、可追溯；不做桌面端。

## 2. 已确认的约束与现有基础

用户确认：**本地评估和选片，视频在远端部署开源模型**。2026-10-05只读检查到本机为RTX5060 Laptop、约8GB显存、31.4GB内存。此为硬件信息，不是新模型运行实测。

保留：相册/缩略图/任务队列、OpenCLIP向量、YuNet/SFace、人名生命周期、CP-SAT及人物数量下限、云端兼容接口、审计与网页。旧Bayesian/PDRR保留为历史对照，不默认恢复训练。

已存在8对授权代理偏好（6胜负、2平局），尚未进入在线重排；其72张来源集合不纳入新的独立留出评测。

本轮新模型美学评分、通用hard/soft解析、偏好记忆重排、视频生成与视频评测均为**待实现**。Enter Photo、社交/分享精修延后，不删除历史规划；不优先扩展人脸算法，除非阻碍主线。

## 3. 模型与部署选择

| 角色 | 首选候选 | 用法 | 运行位置 |
| --- | --- | --- | --- |
| 技术画质 | MUSIQ-KonIQ | 无参考感知质量先验；不把一个总分解释成每种缺陷都定位准确 | 本地，batch1起步 |
| 通用美感 | Aesthetic Predictor V2.5 | SigLIP上的美学预测；与个人偏好分开 | 本地，与其他大模型分时加载 |
| 图文召回 | 保留multilingual OpenCLIP | 缓存图片向量，按任务召回，避免全相册逐图调用VLM | 本地 |
| 结构化理解与候选评审 | Qwen3-VL-2B-Instruct | hard/soft schema、有限候选的属性/理由、偏好记忆条件化判断 | 本地优先；4B量化仅在实测可行后升级 |
| 已有兼容后备 | DeepSeek接口 | 本地模型能力不足时的可选解析/评审后备；非开源本地部署证明 | 明确开关与隐私确认 |
| 图生视频 | Wan2.2-TI2V-5B | 输入照片＋镜头prompt生成RGB短镜头 | 远端NVIDIA GPU |
| 视频评测 | VBench-I2V适用维度＋运动分层诊断 | 参考保持、主体/背景一致性、运动、成像与美学；逐项报告 | 本地能运行的维度本地跑，超显存的同样远端离线跑 |

核对依据：
- [MUSIQ论文](https://arxiv.org/abs/2108.05997)、[pyiqa模型卡](https://github.com/chaofengc/IQA-PyTorch/blob/main/docs/ModelCard.md)：明确采用哪种checkpoint，KonIQ技术质量权重与AVA美学权重不可混称。
- [Aesthetic Predictor V2.5](https://github.com/discus0434/aesthetic-predictor-v2-5)：SigLIP美学评分器，分数不等于个人审美真值。
- [Qwen3-VL-2B模型卡](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct)：选用开放权重多模态理解模型；8GB整条流水线可运行性仍需实测，不能仅按参数量保证。
- [Wan2.2官方仓库](https://github.com/Wan-Video/Wan2.2)、[TI2V-5B模型卡](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B)：支持图生视频。官方720p单卡示例启用卸载后仍要求至少24GB显存；它是选远端24GB级GPU做可行性验证的依据，不是速度或必定不OOM的承诺。
- [VBench官方I2V说明](https://github.com/Vchitect/VBench/blob/master/vbench2_beta_i2v/README.md)：采用自定义输入适用的子指标，不能写成完整官方榜单成绩。

部署首选：远端24GB级GPU做单镜头可行性检查，CPU内存/磁盘按照实际offload配置核验；若不满足再评估48GB，不提前租机器或报固定速度。本地评分、VLM与编码器分时加载，先batch1、限制输入分辨率和上下文。

### 许可证门槛

“公开代码/权重”不等于“所有部件都允许闭源商用”。代码、backbone、预测头、checkpoint、数据许可分别登记。
- Wan2.2代码及TI2V-5B权重标注Apache-2.0，见上面官方仓库与模型卡。
- [pyiqa当前许可](https://github.com/chaofengc/IQA-PyTorch#-license)含非商业限制；[权重集合](https://huggingface.co/chaofengc/IQA-PyTorch-Weights)还要求遵守各原始权重条款。
- [Aesthetic V2.5代码许可](https://github.com/discus0434/aesthetic-predictor-v2-5/blob/main/LICENSE)为AGPL-3.0，不能因SigLIP较宽松就把整个系统称为宽松许可。
- 首先明确求职研究演示的许可兼容边界，逐项审核后才接入；没有确认可用条件的组件可替换，不直接整体复制进主项目或宣称可闭源商用。付费产品发布另做许可核验。

## 4. 分阶段实施

### P0：数据契约与冻结基线（1–2个有效开发日，规划估计）

- 建立asset、photo_analysis、preference_event、shot_plan、video_run、frame_annotation、evaluation_run的版本契约，沿用现有存储，不重写全部基础设施。
- 每张图保存source/license/content_hash/near_duplicate_group；每条评分保存模型revision、预处理和raw_score。只在开发集定标阈值，不在测试集上反复调。
- 每个视频保存参考图、prompt、seed、模型/权重hash、帧数、FPS、分辨率、采样器、步数、镜头边界、耗时、失败与费用记录。
- 内容事实标签、助手代理偏好、直接用户反馈、评审标签分开；不能将模型输出写成真人标签。
- 冻结当前手工质量、无偏好选片、静态/平移缩放成片作为基线。

验收：相同配置可复跑、原图只读、缓存变化可追溯，近重复与同源组不跨记忆/测试划分。

### P1：预训练质量与美学分析（3–5个有效开发日）

每张照片输出三组信息，不先混成一个“万能分数”：
1. 技术质量：MUSIQ感知质量、已有模糊/曝光诊断；严重问题建议排除，允许用户保留。
2. 通用美学：Aesthetic V2.5预测值，用于排序先验，不冒称客观好看程度。
3. 可解释属性：色调、光线、构图、主体、风格等。由VLM在需要时输出固定字段、证据与unknown；它们是模型估计，需抽检。

质量/美学分析保留为按钮任务，显示实际完成数/总数、百分比、取消与缓存；导入不自动触发全套大模型。前端只增加紧凑分数标签与展开说明，不扩大非图片占用。

验收：与旧质量基线同输入对照；若可用公开人工MOS测试集，报告SRCC/PLCC和来源/训练重合边界；项目照片只报告有明确标签的错误检出与代理评审，不自打分证明自己。

### P2：自然语言驱动的集合选片（3–5个有效开发日）

- 本地Qwen把请求转成固定schema：张数、人物配额、排除、范围、风格、用途；本地类型/候选/证据校验。
- OpenCLIP召回，随后只评审受预算限制的候选；人物条件依赖已确认身份，不由大模型猜“我”是谁。
- “多一点建筑”“电影感”默认软偏好；“至少两张夜景”“禁止自拍”只有存在可验证标签时才能变硬约束，高不确定度要确认或拒绝。
- CP-SAT保证硬条件；语义、美学、偏好分在开发集定标后进入目标函数，不直接平均不同量纲的原始分数。
- 约束不可满足时保留原请求并展示独立放松建议；不静默降低要求。
- 解释引用照片和属性证据；支持查看替换候选、锁定与移除，每次操作重验可行性。

验收：固定100条规划中的请求/冲突用例，统计结构化解析正确率、未知条件识别与硬约束满足。任何标作“满足”的输出必须全部通过后端校验；不能只测JSON格式。

### P3：无需训练的个人优化（3–5个有效开发日）

采用“偏好记忆检索＋冻结VLM条件化重排”：
- 输入当前任务、候选照片摘要以及同一配置档案下的历史选择。
- 按任务与视觉内容检索少量相关偏好案例，包含chosen/rejected/tie、理由和来源；区分当前明确请求与长期风格。
- 冻结VLM评估候选的偏好匹配，输出受控分数/理由/依据案例ID；无相关历史允许不变化。
- 个人偏好只影响软排序，不能覆盖数量、人物、排除或锁定等硬约束。
- 用户接受/替换/不喜欢继续留档，可撤销；助手授权代标作为初始偏好池而不是偷偷当成真人点击。
- 新增显式memory模式，record-only保留为无个性化对照，不复活旧训练参数。

验收：同一候选池比较无记忆/有记忆/无关记忆，确保不是因为看了更多图、使用更大模型或泄露测试标签而变化。目前8对只够机制演示；扩充后仍必须区分代理风格迁移与真实用户收益。

### P4：远端开源图生视频与15秒成片（4–7个有效开发日）

- 先把一张图可靠生成为单个短镜头，再接3–5张最终选片的分镜。
- 分镜由冻结VLM输出：顺序、镜头时长、运镜、风格、负向要求、转场；人物动作与场景运动保持保守。
- 远端Wan worker接收已确认上传的图片副本，去除EXIF，不上传整个相册或本地路径；使用认证、请求ID、超时、取消、产物保存与任务恢复。
- 不承诺每次能直接生成任意3秒片段；按模型支持的帧数/FPS生成后裁切，累计约15秒，用FFmpeg完成基础拼接、音量与有许可BGM。
- 逐镜头抽帧评测；有明确失败才在预设总次数内重试。记录所有候选与成本，不能只保存最佳结果。
- 生成失败时保留照片成片/平移缩放回退，但界面明确“照片动效”，不伪装图生视频。

验收：输入输出可追踪，生成任务可恢复；返回真实可播放成片。先验证远端配置和单片耗时，再批准批量预算。

### P5：视频时序与美学评测、求职展示（3–5个有效开发日；随前述各阶段同步）

以镜头为基本单位记录frame_id、timestamp、shot_id、主体/背景稳定、色彩漂移、运动、边缘/形变异常和标注来源；不在正常切镜处误判“帧间不一致”。

- 使用适用的VBench-I2V维度观察参考保持、运动与成像；不是只求一个平均美学分。
- 动态程度/运镜遵循与稳定性同时报告。静态图可能获得低闪烁高一致性，不能因此被判最好。
- 闪烁指标需明确静态或运动补偿适用范围；镜头内部与跨镜头风格/转场分开评估。
- “视频优质率”先冻结rubric：技术可用、参考/主体保持、运动遵循、无严重失真等均过关的片段数/全部尝试片段数；重试/失败/拒绝均统计，不只用成功下载的视频做分母。
- 只有真实产品流量才能谈留存率提升。当前可记录保存率/接受率/编辑次数，但只能在实际用户会话产生后报告；代理操作不能冒充业务指标。

交付：完整演示视频、方法说明、实际失败样本、前后并排图/视频、帧级曲线、耗时显存表、消融与一段复盘；全部同步Obsidian。没有结果时只保留计划，不先填提升百分比。

## 5. 岗位增强项：Alpha与后训练

这两项不同时铺开；先完成核心RGB闭环，再根据目标岗位和失败证据选一个深挖。

### 优先可选：Alpha数据与合成质量

- 人像从[Robust Video Matting](https://github.com/PeterL1n/RobustVideoMatting)作为基线，得到foreground与连续alpha；它不是任意物体的通用透明材质解决方案。
- [SAM2](https://github.com/facebookresearch/sam2)可以做提示分割与跟踪，但mask不等于发丝、玻璃等连续透明度的真值。
- 路径为RGB生成 → 后置matting → 前景/alpha序列 → 多背景合成。RGB生成模型没有因此变成原生RGBA生成器。
- 保存alpha范围、边缘、premultiplied/straight约定；按线性色彩空间的合成约定检查光晕和通道失真。导出PNG序列等保留alpha的格式，并另做预览视频，不能用普通不含alpha的MP4冒充透明结果。
- 有GT时报告SAD/MSE/gradient/connectivity及运动对齐后的边缘闪烁；无GT时只报代理评审和有限诊断。合成输入的已知alpha可作受控测试，不代表真实发丝泛化。
- RVM有GPL等许可边界，具体实现与checkpoint逐项核实。扩展预算与时间另排。

### 可选后训练：必须讲清楚训练了谁

| 方法 | 正确训练对象与目的 | 不可声称 |
| --- | --- | --- |
| VLM的LoRA-SFT | 固定图文输入→结构化属性/分镜/解析输出，改进指令遵循 | 因此解决了视频扩散模型的潜空间时序错误 |
| VLM的DPO | 同一上下文下两份可比较的回答/选片或分镜方案，优化偏好对齐；不是把任意两张图片直接称为DPO样本 | 对冻结API发几个prompt就完成DPO |
| 视频LoRA | 冻结基础视频模型，合法的相同目标风格/运镜序列上做参数高效适配，预算另测 | 少量风格视频必然消除所有抖动/形变 |
| 增量预训练 | 暂不安排；数据、算力、遗忘控制与可归因验证超出当前核心范围 | 套用岗位关键词就有训练成果 |

如果目标重点是“视频生成训练岗位”，核心免训练版本能证明数据/评测/推理优化，但不能代替训练经验。后续优先选择一个有明确失败原因的视频LoRA对照；若预算/许可/数据不足，就诚实保留这个缺口，不虚构经历。

## 6. 验证主张、预算与停止条件

待验证主张仅两条：
- C1：分开使用质量、语义与偏好证据，在硬约束不被破坏的前提下改善任务选片。
- C2：在固定生成预算下，合适的输入和镜头规划能改善图生视频的可用率，而非仅让视频更静止。

不预先称算法创新或效果提升。详细5组验证见 `refine-logs/EXPERIMENT_PLAN.md`：
B1质量/美学，B2约束选片，B3偏好记忆，B4I2V与时序，B5端到端资源/成片。

初始数据量为规划预算，不是已有成果：约300张合法公开照片、100条选片请求、120对开发代理偏好；视频先4图×2种子做环境sanity，再20图×3种子×2种方案=120条生成尝试，外加非生成动效对照。先在开发部分冻结配置，再只打开一次测试部分。公开MOS与独立用户偏好评价另计，未获得则不能报告相应人类效果。

算力不虚报固定时长：第一批测出单镜头分钟数t后，120条预算约为120×t/60 GPU小时＋评测/失败开销；设封顶、超额暂停。24GB是官方推理示例门槛，不是视频LoRA训练配置。此计划不授权租GPU或付费调用。

粗排核心约17–29个有效开发日，属于规划估计，不承诺日历工期；标注复核、模型环境、许可与远端算力可能改变排期。Alpha/训练不计入核心时间。

停止/调整：
- 许可未核清，不把组件集成对外发布。
- 远端单镜头运行不通，先解决环境，不启动批量生成。
- 无独立偏好证据时只称代理风格演示；收益不成立就保留基线。
- 视频“更稳”但不按要求运动，不通过。
- 主评估与筛选使用同一评分器时只称同指标优化；必须补独立维度/盲评再推及感知质量。
- 无真实用户流量，不报告留存率提升。

本轮只输出规划与文档，未修改业务代码、下载模型、训练、租卡、生成视频、提交或推送。使用experiment-plan将每阶段绑定到可检验主张、对照、指标和停止条件；已吸收独立审查关于静止高分、代理标签泄露、VLM-SFT与视频训练区别的意见。
