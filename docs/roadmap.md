# Norma 总体路线与原规划验收

更新：2026-10-05。依据本机《Norma 项目 Codex 总提示词.md》第 1、12–24、27–36 节和用户后续明确调整，对照当前代码重新核定。本文是产品目标与验收的入口；模型接入说明不是总体规划。

## 1. 产品目标没有变

**2026-10-05 最新验收补记（覆盖下方较早状态）：** 照片优先的一页端到端Demo已跑通：104张导入→主动MUSIQ评估/近重复组最佳保留83张→OpenCLIP文字选择4张雪山或9张旅行照→两张照片各自WASD/方向键探索。两场景各7步、165帧、10.3125秒；键盘隔离、刷新恢复、播放和下载SHA通过。当前阶段是“可演示的集成MVP”，不是原全部Core MVP完成或独立效果验证完成。完整证据和限制见 [本轮流程与算法](photo-workflow-20261005.md)。

**2026-10-05 最新优先级覆盖：** 用户明确要求输入一张图后像LingBot一样自由探索，因此当前三天冲刺以 **M8有状态交互探索** 为主，而不是继续扩展固定MP4。保留美学/选片，已有固定视频只算基础能力。实现、许可和待验收边界见 [Enter Photo](enter-photo.md)。下文早期“先核心、再视频/世界”的顺序保留为历史，不再约束本轮执行。

Norma 是 **Personal Multimodal Photo Agent**，不只是“上传几张照片给大模型描述”。

原定重点：个性化多模态选片约 50%，相册理解/检索/RAG 约 20%，视频生成约 15%，有限交互世界约 15%。这是重心分配，不是完成百分比。

完整目标流程：

导入旅行 JPG 相册 → 按需初筛/相似分析/人物聚类 → 统一 Command Bar → 搜索、问相册、子集选片 → 区分硬约束与软偏好 → 个性化集合优化 → Explain / Replace / Lock / Remove / 排序 → 6–10 次可选 A/B → 合理更新个性化推荐 → Create 15s Video → Enter Photo → 简单分享页。

现已增加统一Demo入口；原Library、AI Selection及问图能力保留。入口统一不代表原完整产品清单已全部验收。

## 2. 保留用户后续调整，不恢复过时要求

- Web-only，Python 启动；不再做桌面壳/Tauri。
- 后端优先，UI 以照片为主；仍以 Library / AI Selection / Create 为最终范围，不扩展复杂编辑器。
- 现成模型推理优先，本地检索＋云端大模型；昂贵分析放在召回后，不能导入全相册就逐图调用。
- 不从头训练、不默认自训练。后训练只有在真实失败证据与独立评测支持时少量尝试。
- 原图只读、JPG/JPEG 起步；SQLite 与本地向量即可，不为了技术名词引入集群。
- 每个阶段保留问题、根因、解决、前后证据与量化边界，同步 Obsidian。
- 仅用户明确要求时 commit/push；原提示词中“每个里程碑自动提交”已被后续要求覆盖。
- 视频/世界仍在总路线中，但核心闭环未验收前不优先做，不擅自启动服务器或付费视频生成。

## 4. “不训练”不等于取消个性化

`record-only` 只完成反馈数据收集，不能作为个性化功能的最终状态。它仍保留为纯基线/显式不个性化模式，不自动恢复旧训练。

冻结表征上的相关胜负案例检索与有界软分数修正已实现，并有开发集开关/回退证据；不是DPO或新训练模型。下列为更完整的个性化目标清单，事件覆盖、模型few-shot判断与真实用户收益仍不能视为全部完成：

1. 保存真实用户的 A/B、接受、排除、替换和锁定事件，绑定用户、任务、照片内容与版本。
2. 从同一用户历史中检索与当前任务/候选相关的偏好案例；明确无关、冲突与已撤销的事件。
3. 将少量案例作为 evidence/few-shot 提供给冻结模型，不更新参数；不能把模型标注当作用户真实审美。
4. 得到受控 schema 的软偏好或有证据的候选判断，由本地服务验证来源、候选 ID 和范围。
5. 在 CP-SAT 中保持张数、人物/类别下限、去重及锁定等硬约束，模型不得悄悄覆盖它们。
6. 对比同一候选池下的“无偏好记忆”和“有偏好记忆”，检查合理变化，而不是为了展示变化硬改排序。

实现时需要单独的显式模式/开关与版本化运行快照，不悄悄改变 record-only 的已有行为承诺。稀疏或不相关反馈允许不改结果；原 Demo 应使用能验证相关偏好迁移的真实样例，不要求任意六次点击都必然改变排名。

旧 67D Bayesian / 7D logistic / PDRR 继续作为可复现实验对照，不是 DPO，也不是当前无需训练路线已经完成。

## 5. 后续按这个顺序推进

### 第一步：补 M2 人物命名的可靠基础

2026-10-05 第一批已实现，见 [人物命名与约束选片](person-selection.md)：精确未变化证据保留名字，其他变更进入复核；最小命名网页和人物数量 CP-SAT/替换检查已接通。仍需在用户真实相册重启新服务后进行交互验收，不能宣称完整 M2/M3 或识别效果提升。

- 给 cluster 标记 Me / 自定义称呼 / Unknown，并保存。
- 重新索引时不能把用户命名无条件重置为 Unknown，也不能把名字错误附到变更后的其他人群。
- 人物条件需要区分“没分析”“已分析未发现”“未命名/证据不足”，不能把未知直接当不存在。
- 验收：命名→刷新→重索引→仍正确或明确提示需复核；不越相册串名。

### 第二步：补 M3 结构化请求与执行

- DeepSeek 作为可替换的解析 provider，将自然语言解析为固定 hard/soft schema；本地验证，保留原始 prompt、解析结果和版本。
- 接人物名、人物数量、夜景数量、禁止自拍、子集范围；“多一点建筑/电影感”作为软偏好，不冒充精确配额。
- 类别/自拍证据来自明确版本的模型或用户标签，不把 CLIP 相似度直接当确定真值；高不确定的硬条件应标记无法验证。
- 不支持的条件显式报告，不能吞掉后仍声称满足。
- 冲突保留原请求，输出独立的建议放松方案与 best-effort 状态，严格结果和妥协结果分开标记；从不暗改约束。
- 原示例整体进入测试，不能只测“选 9 张”就判 M3 完成。

### 第三步：补 M4 个性化选片闭环

- 将 Photo-RAG 从独立问图扩展到“为什么这张进入当前集合”：当前请求、约束、评分、竞争照片、相关偏好案例。
- Replace 展示约 4–5 个有效候选，让用户决定；支持 Lock、Remove、排序，动作记录到历史。
- 接无需训练的偏好记忆检索和受约束重排。
- 在真实相册上做可复现 Demo，验证界面展示与后端约束一致。

### 第四步：M5/M6 反馈效率与效果证据

评测随功能同步，不是到最后才测试。先有基线和失败样本，再比较现成模型、检索范围、prompt、偏好记忆策略。保留无个性化、随机提问、启发式主动提问对照；学习式 RL/LoRA/SFT/DPO 仅在条件成立时作为可选实验。

由助手按固定 rubric 标注内容/相关性/证据支持，保留模型来源与分歧复核。用户最新授权助手按审美代标初始偏好：首批 8 对已按 assistant_proxy 记录，见 [代理偏好](proxy-preferences.md)；可以用于初始化与开发，但不得宣称是真人逐张点击或独立用户偏好金标准。开发/测试按相册与近重复组隔离；这批代理数据复用的 72 图源集合排除出新留出评测。报告质量、约束满足、反馈预算、时延和成本，不混淆单次 smoke 与模型效果。

### 第五步：M7 → M8 → M9

- 视频：以已经确认的最终照片集为输入，调用现成视频 provider 生成片段，编排约 15 秒，FFmpeg 合成与版权安全 BGM；不训练生成模型，不做时间线编辑器。
- Enter Photo：先有限动作序列生成的探索片段，再考虑实时 WASD；忠于原场景，不承诺无限世界。
- 分享：最后串起照片、视频和探索入口；不做登录/点赞/评论等商业系统。

## 6. Core MVP 的完成门槛

在一个固定、获准使用的真实 JPG 相册上，保存操作与验收证据：

- [ ] 导入、质量/相似分析、人物聚类、将一人标记 Me。
- [ ] 输入完整请求：“选9张，至少2张有我，不要自拍，多一点建筑，要有夜景，电影感一点，不要太重复。”
- [ ] Developer Mode 展示 hard/soft 解析及证据，不把未支持项当作已支持。
- [ ] 返回满足可验证约束的集合；不可满足时明确原因及独立的妥协方案。
- [ ] Explain 的说法可追到真实证据，Replace 候选有效，Lock/Remove 不破坏已声明状态。
- [ ] 做约6次相关 A/B（用户操作或明确授权的代理标注，来源分开），检索偏好案例并进行无需训练的个性化重排；与无记忆结果同口径比较，代理结果不冒充独立真实用户效果。
- [ ] 保存结果、失败样本、前后图、指标和一段复盘，刷新后可以恢复与核查。

全部通过才可宣布 Core MVP Done。421 项历史测试、143 项供应商专项或单图 DeepSeek 连通均不能替代这份验收。
